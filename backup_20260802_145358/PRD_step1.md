# PRD — 1단계: 냉장고 사진 재료 인식

## 개요
사용자가 냉장고(또는 식재료) 사진을 업로드하면, OpenRouter의 비전(vision) 지원 모델을 이용해 사진 속 식재료를 인식하고 목록으로 추출한다. 이 목록은 2단계(레시피 생성)의 입력으로 사용된다.

## 목표
- 사진 한 장으로부터 식재료 이름 목록을 정확하게 추출한다.
- 인식 결과를 사용자가 검토·수정할 수 있게 한다 (모델이 완벽하지 않으므로).

## 범위
**포함**
- 이미지 업로드 UI (파일 선택 / 드래그 앤 드롭)
- 업로드 이미지를 OpenRouter Chat Completions API로 전송
- 응답에서 재료 목록 파싱 및 화면 표시
- 사용자가 인식된 재료를 추가/삭제/수정

**제외 (다른 단계 담당)**
- 레시피 생성 (2단계)
- 사용자 계정, 결과 저장 (3단계)

## 사용자 플로우
1. 사용자가 냉장고 사진을 업로드한다.
2. "재료 인식하기" 버튼 클릭 → 로딩 상태 표시.
3. API 응답을 받아 재료 목록(예: "계란", "우유", "당근", "대파")을 카드/태그 형태로 표시.
4. 사용자가 목록에서 항목을 삭제하거나 텍스트 입력으로 재료를 추가할 수 있다.
5. "다음 단계로" 버튼으로 확정된 재료 목록을 2단계로 전달한다.

## API 연동 사양
| 항목 | 값 |
|---|---|
| Endpoint | `POST https://openrouter.ai/api/v1/chat/completions` |
| Model | `google/gemma-4-26b-a4b-it:free` |
| 인증 | `Authorization: Bearer $OPENROUTER_API_KEY` (`.env`에서 로드, 하드코딩 금지) |
| 입력 형식 | `messages[0].content`에 `{"type":"image_url","image_url":{"url":"data:image/<mime>;base64,..."}}` + 재료 목록을 JSON으로만 답하라는 지시 텍스트 |

### 프롬프트 설계 요구사항
- 모델에게 "이미지에 보이는 식재료 이름만 JSON 배열로 답하라"고 명시적으로 지시해 후처리 파싱을 단순화한다.
- 예시 출력 형식을 프롬프트에 few-shot으로 포함해 형식 이탈을 줄인다.
- 모델이 JSON이 아닌 형식으로 답하거나 파싱 실패 시, 1회 재시도 후 실패 메시지와 함께 수동 입력을 유도한다.

## 데이터 모델
```
Ingredient {
  name: string          // 재료명
  confidence?: number   // 모델이 신뢰도를 제공하는 경우만 (선택)
  source: "recognized" | "manual"  // 인식됨 vs 사용자가 직접 추가
}
```

## 기능 요구사항
1. 이미지 업로드: JPEG/PNG 지원, 최대 용량 10MB, 클라이언트 측 사전 검증.
2. 업로드 이미지는 base64로 인코딩해 API에 전달 (별도 이미지 서버 업로드 불필요).
3. 재료 인식 결과를 편집 가능한 목록 UI로 표시.
4. 로딩/에러/재시도 상태를 명확히 표시.
5. 무료 티어(`:free`) rate limit(20 RPM / 200 RPD)을 고려해 과도한 연속 요청을 막는 클라이언트 측 디바운스 적용.

## 비기능 요구사항
- 응답 대기 시간 목표: 10초 이내 (모델 응답 지연 시 진행 상태 표시).
- API 키는 서버 사이드 또는 환경변수로만 관리하며 클라이언트 번들에 노출하지 않는다.

## 성공 기준
- 테스트 이미지 업로드 시 실제 존재하는 재료 중 다수를 목록으로 반환한다.
- 인식 실패/형식 오류 시에도 사용자가 수동으로 재료를 입력해 다음 단계로 진행할 수 있다.

## 다음 단계 인터페이스
2단계는 이 단계에서 확정된 `Ingredient[]` 목록(재료명 배열)을 입력으로 받는다.

## 리스크 / 참고 사항
- 초기에는 `google/gemma-4-31b-it:free`를 사용했으나, 실제 냉장고 사진으로 테스트한 결과 OpenRouter 업스트림(Google AI Studio 공유 무료 풀)에서 지속적인 429 rate limit이 발생해 `google/gemma-4-26b-a4b-it:free`로 교체함 (2026-08-01 테스트 기준, 후자는 정상 응답 확인).
- `:free` 모델은 무료 티어 특성상 응답 지연·오류가 간헐적으로 발생할 수 있음. 재시도 로직 또는 유료 모델 폴백을 향후 고려.
